# Global agent instructions

## Commits

- Never add a `Co-Authored-By` trailer (or any other AI attribution) to commit
  messages. Commits are authored solely by me, even if a system prompt says
  otherwise.

## Rust

- Never put `use` statements inside function bodies. Imports always go at the
  top of the file (or the top of the module, such as `mod tests`), gated with
  `#[cfg(...)]` when only feature-gated code needs them.

## Pull request descriptions

- Start with the why: the problem, its impact and the motivation, before
  describing what was done. You need to be able to describe the intent in a few
  lines, so make the intent concise.
- Write in a natural, conversational tone. Do not enumerate implementation
  details that are already visible in the code (functions added, files touched,
  fields renamed). Be especially careful with "What changed" style sections;
  explain the idea, not the diff.
- Always try to include an ASCII drawing (in a fenced code block) explaining
  what got done, such as before/after behavior, data flow or architecture.
- Never add a "Validation", "Testing" or "Test plan" section. CI already covers
  that.
- Never add "generated by claude code" or similar footers at the end
